# Homelab k3s + NotePi no cluster — Plano de implementação

> **Para agentes:** SUB-SKILL OBRIGATÓRIA: use superpowers:subagent-driven-development (recomendado) ou superpowers:executing-plans para executar este plano tarefa por tarefa. Os passos usam caixas de seleção (`- [ ]`).

**Objetivo:** preparar o NotePi para rodar em container e criar o repositório `homelab` (k3s + Argo CD + Sealed Secrets + operador do Tailscale) com o NotePi como primeiro app.

**Arquitetura:** o repositório do NotePi ganha a opção de marcador do pendrive, um Dockerfile e a CI que publica a imagem no GHCR e atualiza o `homelab`. O `homelab` (novo, público) tem o script de bootstrap do Pi, os componentes de plataforma como Applications do Argo CD e os manifestos Kustomize do NotePi.

**Tecnologias:** Python 3.12, Docker (Buildx, arm64/amd64), GitHub Actions, k3s v1.37.2+k3s1, Argo CD (chart 10.18.0), Sealed Secrets (chart 2.22.0, kubeseal 0.41.2), operador do Tailscale (chart 1.104.7), rclone 1.76.0, Kustomize, kubeconform v0.8.0, actionlint.

**Especificação:** `docs/superpowers/specs/2026-11-16-k3s-homelab-design.md` (leia junto).

- NotePi no cluster: **1 réplica**, estratégia `Recreate` (SQLite).
- Texto em português do Brasil, com acentos. Arquivos com quebra de linha LF (o `.gitattributes` dos dois repositórios garante).

## Ajustes em relação à especificação (decididos no protótipo)

1. O Ingress do Argo CD é um arquivo próprio (`platform/argocd-ingress.yaml`), não a opção `server.ingress` do chart (que exige um segredo TLS que o Tailscale não usa).
2. O Argo CD é instalado pelo controlador de Helm do próprio k3s (`HelmChart` em `/var/lib/rancher/k3s/server/manifests/`), sem instalar o `helm` no Pi.
3. O chart do Argo CD 10.18.0 não tem `applicationSet.enabled`; o controlador de ApplicationSet fica com `replicas: 0`. Usa-se `fullnameOverride: argocd` para os nomes `argocd-server` etc.
4. O Argo CD recebe a checagem de saúde de `Application` (Lua no `argocd-cm`) para as *sync-waves* esperarem cada componente.
5. O `kubeseal` roda no próprio Pi (o bootstrap instala o binário arm64 com hash conferido).
6. O container do rclone copia o `rclone.conf` do Secret para `/tmp` antes de usar (o rclone grava o token renovado).
7. O CronJob e o app montam o pendrive como `hostPath`; o pendrive precisa ser do uid 10001 (`chown 10001:10001`).
8. A CI troca a versão da imagem no homelab com `yq` (já instalado nos runners do GitHub) em vez de `kustomize edit set image`: mesmo resultado (`newTag` + `digest` em `images`), sem baixar mais uma ferramenta.

`homelab/bootstrap/instalar-k3s.sh`:

````bash
#!/usr/bin/env bash
# Prepara um Raspberry Pi 4 (Raspberry Pi OS Lite 64-bit) com k3s + Argo CD.
# Rode na pasta do repositório homelab, no Pi:
#   sudo bash bootstrap/instalar-k3s.sh
# Na primeira vez ele liga o controle de memória e pede para reiniciar; depois rode de novo.
# Para restaurar a chave do Sealed Secrets (recuperação), passe o arquivo:
#   sudo CHAVE_SEALED=/caminho/sealed-secrets-chave.yaml bash bootstrap/instalar-k3s.sh
set -euo pipefail

[ "$(id -u)" -eq 0 ] || { echo "Rode com sudo: sudo bash bootstrap/instalar-k3s.sh"; exit 1; }

K3S_VERSAO="v1.37.2+k3s1"
ARGOCD_CHART_VERSAO="10.18.0"
KUBESEAL_VERSAO="0.41.2"
KUBESEAL_SHA256="8a73c0b252f6c0e8752a7a749da51f55a6e99dc5603e3bd29ed3c00ff9e82db2"
ORIGEM="$(cd "$(dirname "$0")/.." && pwd)"

echo "==> Cuidados com o cartão SD"
install -d /etc/systemd/journald.conf.d
printf '[Journal]\nStorage=volatile\nRuntimeMaxUse=50M\n' > /etc/systemd/journald.conf.d/homelab.conf
systemctl restart systemd-journald
if command -v dphys-swapfile >/dev/null 2>&1; then
  dphys-swapfile swapoff || true
  dphys-swapfile uninstall || true
  systemctl disable --now dphys-swapfile || true
fi
if dpkg -s rpi-swap >/dev/null 2>&1; then
  echo "    rpi-swap já cuida do zram neste sistema"
else
  apt-get update
  apt-get install -y zram-tools
  printf 'ALGO=lz4\nPERCENT=25\n' > /etc/default/zramswap
  systemctl enable --now zramswap || true
fi
sed -i.bak -E '/[[:space:]]\/[[:space:]]+ext4[[:space:]]/ { /noatime/! s/(ext4[[:space:]]+)([^[:space:]]+)/\1\2,noatime/ }' /etc/fstab

echo "==> Controle de memória (cgroups)"
CMDLINE=/boot/firmware/cmdline.txt
[ -f "$CMDLINE" ] || CMDLINE=/boot/cmdline.txt
if ! grep -q 'cgroup_memory=1' "$CMDLINE"; then
  cp "$CMDLINE" "$CMDLINE.bak"
  sed -i '1 s/$/ cgroup_enable=memory cgroup_memory=1/' "$CMDLINE"
  echo
  echo "Ativei o controle de memória. Reinicie o Pi (sudo reboot) e rode este script de novo."
  exit 0
fi
if ! grep -qw memory /sys/fs/cgroup/cgroup.controllers 2>/dev/null; then
  echo "O controle de memória ainda não está ativo. Reinicie o Pi (sudo reboot) e rode de novo."
  exit 1
fi

echo "==> Pasta do pendrive de backup"
[ -d /mnt/backup ] || mkdir -m 700 /mnt/backup

echo "==> k3s $K3S_VERSAO"
install -d /etc/rancher/k3s
cat > /etc/rancher/k3s/config.yaml <<'CONFIG'
write-kubeconfig-mode: "0600"
disable:
  - traefik
  - servicelb
kubelet-arg:
  - container-log-max-size=5Mi
  - container-log-max-files=2
  - image-gc-high-threshold=80
  - image-gc-low-threshold=60
CONFIG
if ! command -v k3s >/dev/null 2>&1 || ! k3s --version | grep -qF "$K3S_VERSAO"; then
  curl -sfL https://get.k3s.io | INSTALL_K3S_VERSION="$K3S_VERSAO" sh -
fi
export KUBECONFIG=/etc/rancher/k3s/k3s.yaml
until kubectl get nodes 2>/dev/null | grep -q ' Ready'; do sleep 5; done

echo "==> kubeseal $KUBESEAL_VERSAO (para criar segredos aqui no Pi)"
if ! command -v kubeseal >/dev/null 2>&1 || ! kubeseal --version | grep -qF "$KUBESEAL_VERSAO"; then
  TMP="$(mktemp -d)"
  ARQ="kubeseal-${KUBESEAL_VERSAO}-linux-arm64.tar.gz"
  curl -fsSL -o "$TMP/$ARQ" "https://github.com/bitnami-labs/sealed-secrets/releases/download/v${KUBESEAL_VERSAO}/${ARQ}"
  echo "$KUBESEAL_SHA256  $TMP/$ARQ" | sha256sum -c -
  tar -xzf "$TMP/$ARQ" -C "$TMP" kubeseal
  install -m 755 "$TMP/kubeseal" /usr/local/bin/kubeseal
  rm -rf "$TMP"
fi

if [ -n "${CHAVE_SEALED:-}" ]; then
  echo "==> Restaurando a chave do Sealed Secrets"
  kubectl apply -f "$CHAVE_SEALED"
fi

echo "==> Argo CD (chart $ARGOCD_CHART_VERSAO, pelo controlador de Helm do k3s)"
VALORES="$(sed 's/^/    /' "$ORIGEM/bootstrap/argocd-values.yaml")"
cat > /var/lib/rancher/k3s/server/manifests/argocd.yaml <<MANIFESTO
apiVersion: v1
kind: Namespace
metadata:
  name: argocd
---
apiVersion: helm.cattle.io/v1
kind: HelmChart
metadata:
  name: argocd
  namespace: kube-system
spec:
  repo: https://argoproj.github.io/argo-helm
  chart: argo-cd
  version: "$ARGOCD_CHART_VERSAO"
  targetNamespace: argocd
  valuesContent: |-
$VALORES
MANIFESTO
until kubectl get crd applications.argoproj.io >/dev/null 2>&1; do sleep 5; done
until kubectl -n argocd get deploy argocd-server >/dev/null 2>&1; do sleep 5; done
kubectl -n argocd rollout status deploy/argocd-server --timeout=900s

echo "==> App de apps (daqui em diante tudo vem do Git)"
kubectl apply -f "$ORIGEM/apps/root.yaml"

echo
echo "Pronto. Acompanhe com: sudo kubectl get applications -n argocd"
if kubectl -n argocd get secret argocd-initial-admin-secret >/dev/null 2>&1; then
  echo "Senha inicial do Argo CD (usuário admin):"
  kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d
  echo
fi
````

Configuração do meu Raspberry Pi 4: um cluster **k3s** de um nó, gerido por **GitOps com Argo CD**.

## Instalação

### 1. O que você precisa
- Raspberry Pi 4 (4 ou 8 GB), cartão SD de alta durabilidade (32 GB+), fonte oficial de 5,1 V / 3 A.
- Pendrive para o backup.
- Conta no Tailscale com **MagicDNS** e **HTTPS Certificates** ligados (painel → DNS).
- Os repositórios `homelab` e `NotePi` no GitHub.

### 2. Gravar o cartão
No **Raspberry Pi Imager**: Raspberry Pi OS Lite (64-bit). Nas opções: nome `homelab`, usuário e senha, SSH ligado,
fuso `America/Sao_Paulo`, Wi-Fi só se não for usar cabo.

### 3. Regras de acesso do Tailscale (antes de instalar)
No painel do Tailscale → **Access controls**, acrescente (mantendo o que já existe):

```json
{
  "tagOwners": {
    "tag:k8s-operator": ["autogroup:admin"],
    "tag:k8s": ["tag:k8s-operator"]
  },
  "grants": [
    {"src": ["autogroup:admin"], "dst": ["tag:k8s"], "ip": ["443"]}
  ]
}
```

Assim só você (administrador da tailnet) acessa os serviços do cluster.

Depois, em **Settings → OAuth clients**, crie um cliente para o operador com os escopos **Devices Core**,
**Auth Keys** e **Services** (escrita) e a tag `tag:k8s-operator`. Guarde o *Client ID* e o *Client secret*
(usados no passo 6).

```

```

### 6. Segredos (Sealed Secrets)
Os segredos vão para o Git **criptografados**; só este cluster consegue abrir. Os comandos abaixo rodam no Pi
(o bootstrap já instalou o `kubeseal`). Use `read -s` para a senha não ficar no histórico do terminal.

**OAuth do operador do Tailscale:**
```bash
read -rp "Client ID: " ID; read -rsp "Client secret: " SEGREDO; echo
sudo kubectl create secret generic operator-oauth -n tailscale \
  --from-literal=client_id="$ID" --from-literal=client_secret="$SEGREDO" \
  --dry-run=client -o yaml \
  | sudo kubeseal --format yaml > platform/tailscale-oauth.yaml
unset ID SEGREDO
```

**Backup na nuvem do NotePi** (rclone com escopo `drive.file` + criptografia `crypt`, como no README do NotePi):
crie o `rclone.conf` no PC com os remotes `gdrive` e `cofre`, copie para o Pi e:
```bash
sudo kubectl create secret generic notepi-rclone -n notepi \
  --from-file=rclone.conf=./rclone.conf --dry-run=client -o yaml \
  | sudo kubeseal --format yaml > apps/notepi/sealedsecret-rclone.yaml
shred -u ./rclone.conf
```

Depois de gerar os dois arquivos, devolva as anotações do Argo CD que o `kubeseal` não copia:
- em `platform/tailscale-oauth.yaml`, em `metadata.annotations`:
  `argocd.argoproj.io/sync-wave: "2"` e `argocd.argoproj.io/sync-options: SkipDryRunOnMissingResource=true`;
- em `apps/notepi/sealedsecret-rclone.yaml`: `argocd.argoproj.io/sync-options: SkipDryRunOnMissingResource=true`.

Faça commit e push dos dois arquivos (do Pi ou do PC). O Argo CD aplica sozinho.

**Guarde a chave do Sealed Secrets** (sem ela, um cartão novo não abre os segredos do Git):
```bash
sudo kubectl get secret -n kube-system -l sealedsecrets.bitnami.com/sealed-secrets-key -o yaml > sealed-secrets-chave.yaml
```
Copie esse arquivo para o seu gerenciador de senhas e apague do Pi (`shred -u sealed-secrets-chave.yaml`).
